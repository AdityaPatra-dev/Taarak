# CORE MODULE: Database (`lib/core/database/`)

## Overview

This is the app's entire offline-first local persistence layer: a single Drift/SQLite database (`AppDatabase`), 17 entity tables plus one sync outbox table, 14 per-entity repositories implementing a shared `LocalRepository<T, ID>` contract, and 3 hand-written DAOs for access patterns that don't fit that contract (audit log, alert acknowledgements, sync queue).

**File inventory (39 files):**
- `app_database.dart` — the `AppDatabase` class, table registration, schema version, migration strategy.
- `app_database.g.dart` — Drift's generated code (16,163 lines): one `$<Table>Table` class, one `<Entity>` `DataClass`, and one `<Table>Companion` `UpdateCompanion` per declared table. STATUS: GENERATED — do not hand-edit; regenerated by `dart run build_runner build` whenever a table file changes.
- `database_result_guard.dart` — the shared `Result`-wrapping try/catch used by every repository/DAO.
- `alert_acknowledgement_dao.dart`, `audit_log_dao.dart`, `sync_queue_dao.dart` — the three DAOs that don't implement `LocalRepository`.
- `tables/` (17 files) — one `Table` subclass per entity, plus `sync_queue_table.dart`.
- `repositories/` (14 files) — one `LocalRepository<T, String>` implementation per entity that has simple CRUD needs (i.e. every table except `LocalAuditEvents`, `LocalAlertAcknowledgements`, and `SyncQueueEntries`, which get their own DAOs instead).

**Schema version: 11** (declared in `AppDatabase.schemaVersion`).

**Migration strategy** (`AppDatabase.migration`, in `app_database.dart`): `onCreate` calls `m.createAll()`. `onUpgrade` — for **any** version jump — deletes every table (`for (final table in allTables) await m.deleteTable(...)`) and recreates the full schema from scratch via `m.createAll()`. This is **destructive**: no data-preserving per-version migration exists anywhere in this codebase. The doc comment on `migration` explains this is a deliberate pre-release shortcut ("no real user data yet worth preserving") to avoid writing migrations for schema history that changed rapidly without the version being bumped each time; it explicitly flags that this must be replaced with real migrations before a stable release. Any handover engineer must treat this as a known, intentional gap, not an oversight.

**Web support**: `AppDatabase`'s constructor configures `DriftWebOptions(sqlite3Wasm: ..., driftWorker: ...)` pointing at `sqlite3.wasm` / `drift_worker.js` served from `web/`, so the same database code runs on Flutter web via WASM SQLite.

**The repository pattern used throughout**: every `Local<Entity>Repository` implements `core/repository/local_repository.dart`'s `LocalRepository<T, ID>` (`getById`, `getAll`, `save`, `delete`), takes an `AppDatabase` in its constructor, and wraps every Drift call in `guardCacheOperation` (see below) so callers never see a raw Drift/SQLite exception — only `Result<T>`. `save` is always `insertOnConflictUpdate` (upsert), never a separate insert/update split. `getById` on a missing row returns `Result.failure(CacheFailure(...))`, never a null success.

## `database_result_guard.dart`

- **Purpose**: The single shared `Future<Result<T>> guardCacheOperation<T>(Future<T> Function() action)` function used by all 17 repositories/DAOs. Catches `CacheException` specifically (maps to `CacheFailure(error.message)`, logs via `AppLogger.error`) and falls back to a generic `CacheFailure()` for any other exception.
- **Status**: IMPLEMENTED.
- **Depends on**: `core/error/app_exception.dart`, `core/error/failure.dart`, `core/logging/app_logger.dart`, `core/repository/result.dart`.
- **Depended on by**: every file in `repositories/`, plus `alert_acknowledgement_dao.dart`, `audit_log_dao.dart`, `sync_queue_dao.dart`.

## Wiring

`lib/core/providers/core_providers.dart` (documented fully in `docs/modules/core_infrastructure.md`) constructs `AppDatabase` once as a Riverpod `Provider` (`appDatabaseProvider`, disposed via `ref.onDispose(db.close)`) and every repository/DAO above as its own `Provider` built on top of it — nothing in this directory constructs `AppDatabase` itself outside of tests.

## Test Coverage

- `test/core/database/local_database_smoke_test.dart` — real on-disk `NativeDatabase` round-trip (write while "offline," close, reopen, read back) proving persistence survives an app restart; in-memory `LocalShelterRepository` save/list/delete; `SyncQueueDao` pending→synced transition and `markFailed` using an injected clock instead of the wall clock.
- `test/core/foundation_smoke_test.dart` — exercises the `LocalRepository`/`Result` *contract* generically via a hand-rolled in-memory fake repository (not a real Drift table), plus an `ApiClient` offline-failure case. Confirms the abstraction is usable end-to-end but does not touch `AppDatabase` itself.
- No test file directly exercises `AuditLogDao` or `AlertAcknowledgementDao` in `test/core/`; their behavior is verified indirectly elsewhere (e.g. `test/features/alerts/`, outside this module's read scope).
- No migration test exists — the destructive `onUpgrade` path (drop-and-recreate) has no automated coverage.
